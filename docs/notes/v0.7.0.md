Relay 0.7.0 adds Agent mode: a model that works in a folder.

### New

- **Chat / Agent.** A switch in the title bar, next to the sidebar button, moves between your chats and your Agent sessions. Each has its own list, its own search and its own New button, and Relay remembers which one you were in.
- **Sessions work in a folder.** Pick one with the folder chip in the composer, or leave it empty and Relay makes a workspace folder for the session. The sidebar groups sessions by folder; the title bar shows the folder and, in a git repository, the branch. Deleting a session asks whether its workspace goes too; a folder you picked is never deleted.

- **The agent works on files.** In a session the model can read, create, edit and delete files in its folder, list them and search them. Each change shows as a card with the changed lines in red and green.
- **Permission modes.** A chip next to the model picks how much the agent may do on its own: **Ask every time** (each change waits for your OK, with the diff in front of you), **Accept edits** (changes in the folder just happen) or **Bypass** (everything runs, shown in amber). Shift+Tab switches between them, and a new session starts with the one you used last. An approval can also switch the session to Accept edits from there on. Reading anything outside the folder asks first; keys and passwords (`.ssh`, browser profiles, password managers and the like) are never read in Bypass.
- **The folder's own instructions.** A session reads the folder's `AGENTS.md` (or `CLAUDE.md`) when it starts, and follows it. "Reload instructions" in the folder chip reads it again.
- **Which models call tools.** Relay now knows which models can call tools: from what the server says, or by asking the model once with a tiny request. Models that can't carry a "no tools" badge in Agent mode, and Settings → Models has a Tools ability with a Check button.

- **Everything the agent changes can be undone.** Before every change, Relay records the folder's files (not `node_modules`, `.git` and other folders that can be rebuilt, and nothing over 50 MB). Each step's card has **Restore to before this**: changed files go back, deleted ones return, files created since are removed, and the restore itself can be undone. It covers changes made by scripts too, not only by the file tools.
- **Files panel.** The button in the title bar opens the session's files: what it created, changed or deleted, each file's saved versions, the changes since any of them, and Restore for a single file. Files too big to protect are listed there.
- **Checkpoints stay small.** Each file's content is stored once, however many steps share it, and old sessions' history is trimmed to the last 5 versions of each file when a folder's store passes 2 GB. A step that can no longer be restored says so on its card.

- **The agent runs commands.** PowerShell always, Git Bash when it's installed. A command runs in the session's folder with no window, stops after 2 minutes unless the model asks for longer (up to 10), and its card folds away; open it to watch the output live, like a terminal. Stopping the reply ends the command and everything it started.
- **Background processes.** A dev server or a watcher can keep running while the agent works on. The title bar shows how many are running, with Stop for each; they all end when the session is deleted or Relay quits.

- **The model can ask you.** When it needs a decision only you can make, it asks up to four questions with options to pick from (or your own answer) and waits. In Auto and Bypass it doesn't stop to ask: it lists its questions and assumptions at the end instead. Chats with MCPs on have it too.
- **To-do list.** For work with several steps the model keeps a checklist you can follow, ticked as it goes.

- **Auto mode.** For leaving the agent to work on its own: nothing waits for you. Each command is read before it runs (PowerShell by PowerShell's own parser, Bash and cmd by Relay), including the scripts and code it starts, and steps that could lose something are refused with a reason: deleting files, destructive git, writing outside the folder, reading keys and passwords, uploading files, publishing, global installs, system changes and code Relay can't read. The model carries on with the rest and lists what was blocked at the end.
- **The blocked list.** "Blocked: n" in the title bar lists what Auto refused, each with **Run it now** (a checkpoint is taken first, so it can be undone).
- **Auto may push and publish.** A switch in the folder chip lets Auto run `git push`, `gh pr create`, `npm publish` and the like for that folder. Force pushes stay refused.
- **Secrets stay out of Auto's commands.** Environment variables that hold tokens, keys and passwords are removed from commands in Auto. The composer lists them, and **Manage** lets one through for the folder; its value is then hidden in what the model reads.
- **Python packages go into the folder.** In Auto, `pip install` goes into a `.venv` in the folder, made the first time with the computer's packages still visible.
- In Ask modes, an approval card for a command Auto would refuse says so.

### Fixed

- **Settings' segmented buttons** (Theme, Conversation width, Send with) show which choice is on again.
